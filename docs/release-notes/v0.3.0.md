# QoR Guard v0.3.0 (experimental)

QoR Guard is a command-line tool that compares Yosys and nextpnr-ice40 implementation reports between two runs. It reports resource and timing changes, and sets an exit code from thresholds you configure.

**This is an experimental release.** It isn't production-ready, and it has no established users.

## What's included
- **Capture** Yosys `stat -json` or a Yosys log stat table, plus one or more nextpnr-ice40 `--report` JSON files. Inputs are copied and hashed with SHA-256.
- **Manifest (`capture --manifest`)** records seeds, failed runs, tool versions, device, commit and required clocks, exactly as you declare them.
- **Compare** against a stored baseline, showing:
  - absolute and percentage changes;
  - logic-cell utilisation and headroom;
  - BRAM use;
  - a comparison type you state (`revision`, `configuration` or `unknown`).
- **Observed Fmax ranges** across several runs. These are for reporting only and never change the exit code.
- **Required-clock checks** against a declared frequency, judged on the observed minimum. These are frequency margins, not period slack.
- **Failed runs a manifest declares** can never produce a PASS.
- **Markdown reports.**

## Exit codes

| Code | Meaning |
|---|---|
| 0 | Every applicable check was evaluated and met |
| 1 | A threshold was exceeded, or a required clock was missed |
| 2 | Evidence is incomplete, or requirements are inconsistent |
| 3 | Bad input |

Command-line syntax errors also exit 2.

## Tested environment
- **Windows 11, Python 3.14.4 only.** Linux and macOS are untested.
- **Real reports:** Yosys 0.70+255 and nextpnr-ice40 0.11.1-83 on iCE40 HX8K, checked privately by the maintainer. Those reports aren't distributed.
- **UP5K:** limited internal evaluation, not covered by the public tests.
- **Other versions and iCE40 parts** are untested.

## Not supported
- ECP5, Gowin, Xilinx/openXC7, Vivado, Quartus and Diamond.
- DSP and SPRAM metrics, power, critical-path comparison, and root-cause analysis.
- CI integration, pull-request comments, named baselines and BRAM headroom comparisons.

## Thresholds
- **`config/thresholds.example.json`** holds illustrative values only. They aren't validated recommendations and aren't statistically calibrated.
- **Built-in defaults** used without `--config` are legacy values of unknown rationale.
- Set your own thresholds for your design.

## Tests
`python -I -B -m unittest discover -s tests -t .` should give 258 tests: **255 passed, 0 failed, 3 skipped**.
- **Skipped tests:** they need private evaluation data that isn't distributed.
- **Fixtures:** all test fixtures are synthetic, so the public tests show the code handles the expected file layouts, not that it's compatible with real tool output.

## Privacy
Reports and `run.json` files record absolute local paths. Check them before sharing, and keep generated output out of Git. `.gitignore` covers `runs/`.
